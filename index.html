4. Framework

4.1. Registration attempts

A registration attempt is a struct representing an in-flight or completed DBSC registration started by process a session registration. It has the following items:

registration URL

A URL.

provider URL

Null or a URL, initially null.

provider session ID

Null or a string, initially null.

end time

Null or a coarsened moment on the wall clock, initially null.

success

A boolean, initially false.

resulting session

A device bound session or null, initially null.

reason

A string or null, initially null.

code

Null or a 16-bit unsigned integer, initially null.

associated document

A Document or null, initially null.

completed

A boolean, initially false.

A registration waiter is a struct that tracks a pending waitForRegistrations() call and the registration attempts it waits on. It has the following items:

promise

A Promise.

environment

An environment settings object.

captured attempts

A list of completed registration attempts.

remaining

A set of registration attempts.

4.2. Per-document registration state

A document tracks its same-origin DBSC registrations while they are in flight, buffers their outcomes once they finish.

Each Document has:

  • pending registrations, a set of registration attempts, initially empty.

  • registration buffer, a list of completed registration attempts, initially empty.

  • registration waiters, a list of registration waiters, initially empty.

User agents should cap the size of a Document’s registration buffer at an implementation-defined limit, removing the earliest-appended entries first.

When the user agent clears cookies or site data for an origin or site (including via `Clear-Site-Data` [clear-site-data]), it must empty the registration buffer of each Document whose origin is affected.

This specification defines the following unloading document cleanup steps given a Document document:

  1. If document’s salvageable state is true, then return.

  2. Let waiters be a clone of document’s registration waiters.

  3. Empty document’s pending registrations.

  4. Empty document’s registration buffer and registration waiters.

  5. For each waiter of waiters:

    1. Reject waiter’s promise with an "AbortError" DOMException.

A subresource request already has a target window, so the browser queues the new attempt onto its document. During a navigation, the destination document does not exist yet, so attempts stay on the navigation request until HTML creates the document and attaches the same-origin ones.

To start a registration attempt given a request originating request and a URL registration URL, with an optional URL provider URL and an optional string provider session ID:

  1. Assert: originating request’s current URL’s origin is same site with registration URL’s origin.

  2. Let attempt be a new registration attempt whose registration URL is registration URL.

  3. If provider URL was given, then set attempt’s provider URL to provider URL.

  4. If provider session ID was given, then set attempt’s provider session ID to provider session ID.

  5. If originating request is a navigation request:

    1. Append attempt to originating request’s registration attempts.

    2. Return attempt.

  6. Let client be originating request’s client.

  7. If client is null or client’s global object is not a Window, then return attempt.

  8. If client’s origin is not same origin with registration URL’s origin, then return attempt.

  9. Let window be client’s global object.

  10. Queue a global task on the networking task source given window to run these steps:

    1. Attach a registration attempt given window’s associated Document and attempt.

  11. Return attempt.

Note: HTTP-network fetch runs this step while processing response headers, so the task enters the networking task source before fetch() resolves. Multi-process implementations need to preserve that ordering across IPC.

Note: If a Service Worker forwards a request with respondWith(fetch(...)), that fetch() creates a new request whose client is the Service Worker, so the Document does not record registrations from its response.

To attach a registration attempt given a Document document and a registration attempt attempt:

  1. If document’s browsing context is null, then return.

  2. If document’s origin is not same origin with attempt’s registration URL’s origin, then return.

  3. Set attempt’s associated document to document.

  4. If attempt’s completed is true, then append attempt to document’s registration buffer.

  5. Otherwise, append attempt to document’s pending registrations.

To attach navigation registration attempts given a Document document and navigation params navigationParams:

  1. Let request be navigationParams’s request.

  2. If request is null, then return.

  3. For each attempt of request’s registration attempts:

    1. Attach a registration attempt given document and attempt.

When a registration finishes, the browser records its outcome and queues a task on the associated document to buffer the attempt and settle any waiting callers.

To complete a registration attempt given a registration attempt attempt and a boolean success, with an optional device bound session resulting session, an optional string reason, and an optional 16-bit unsigned integer code:

  1. Set attempt’s end time to the current coarsened wall time.

  2. Set attempt’s success to success.

  3. If resulting session was given, then set attempt’s resulting session to resulting session.

  4. If reason was given, then set attempt’s reason to reason.

  5. If code was given, then set attempt’s code to code.

  6. Set attempt’s completed to true.

  7. Let document be attempt’s associated document.

  8. If document is null, then return.

  9. Queue a global task on the networking task source given document’s relevant global object to finalize a registration attempt given document and attempt.

Note: This algorithm runs in parallel while attachment runs on the Document event loop. Multi-threaded implementations need synchronization around associated document and completed so an attempt finishing during handoff still moves into registration buffer.

To finalize a registration attempt given a Document document and a registration attempt attempt:

  1. If document’s pending registrations contains attempt:

    1. Remove attempt from document’s pending registrations.

    2. Append attempt to document’s registration buffer.

  2. Settle registration waiters given document and attempt.

To settle registration waiters given a Document document and a registration attempt attempt:

  1. Let waiters be a clone of document’s registration waiters.

  2. For each waiter of waiters:

    1. If waiter’s remaining does not contain attempt, then continue.

    2. Remove attempt from waiter’s remaining.

    3. Append attempt to waiter’s captured attempts.

    4. If waiter’s remaining is not empty, then continue.

    5. Remove waiter from document’s registration waiters.

    6. Let results be the result of collecting registration results given waiter’s captured attempts and waiter’s environment.

    7. Resolve waiter’s promise with results.

5. Extensions to the Navigator interface

partial interface Navigator {
  [SecureContext, SameObject] readonly attribute DeviceBoundSessionManager deviceBoundSessions;
};

Each Navigator has an associated device bound session manager (null or a DeviceBoundSessionManager), initially null.

The deviceBoundSessions getter steps are:

  1. If this’s device bound session manager is null, then set this’s device bound session manager to a new DeviceBoundSessionManager in this’s relevant realm.

  2. Return this’s device bound session manager.

6. The DeviceBoundSessionManager interface

The DeviceBoundSessionManager interface lets scripts inspect active device bound sessions and wait for pending registrations on the current Document.

[Exposed=Window, SecureContext]
interface DeviceBoundSessionManager {
  Promise<sequence<DeviceBoundSessionInfo>> getSessions();
  Promise<sequence<DeviceBoundSessionRegistrationResult>> waitForRegistrations(
    optional DeviceBoundSessionWaitOptions options = {}
  );
};

dictionary DeviceBoundSessionWaitOptions {
  AbortSignal signal;
};

6.1. getSessions() method

getSessions() reads non-expired sessions from the session store in the background and resolves with info dictionaries for the ones visible to the caller.

When getSessions() is called:

  1. Let global be this’s relevant global object.

  2. If global’s associated Document is not fully active, then return a promise rejected with an "InvalidStateError" DOMException in this’s relevant realm.

  3. Let environment be this’s relevant settings object.

  4. Let url be environment’s creation URL.

  5. Let promise be a new promise in this’s relevant realm.

  6. Run the following steps in parallel:

    1. Let sessions be the result of reading active sessions given url.

    2. Queue a global task on the networking task source given global to resolve promise with the result of collecting visible session infos given sessions and environment.

  7. Return promise.

To read active sessions given a URL url:

  1. If url’s host is null, then return « ».

  2. Let domain be url’s host’s registrable domain.

  3. If domain is null or session store[domain] does not exist, then return « ».

  4. Let now be the current coarsened wall time.

  5. Let sessions be a new list.

  6. For each session of session store[domain]'s values:

    1. If session’s expiration timestamp is not before now, then append session to sessions.

  7. Return sessions.

To collect visible session infos given a list of device bound sessions sessions and an environment settings object environment:

  1. Let results be a new list.

  2. For each session of sessions:

    1. If determine session visibility given environment and session is "visible", then append the result of creating a session info given session to results.

  3. Return results.

6.2. waitForRegistrations() method

waitForRegistrations() waits for any registrations currently in flight on the document and resolves with the buffered outcomes sorted by completion time. When no registrations are in flight, it resolves right away. It ignores registrations started after the call.

A DeviceBoundSessionWaitOptions dictionary configures waitForRegistrations():

signal, of type AbortSignal

An AbortSignal to abort the wait.

When waitForRegistrations(options) is called:

  1. Let global be this’s relevant global object.

  2. Let document be global’s associated Document.

  3. If document is not fully active, then return a promise rejected with an "InvalidStateError" DOMException in this’s relevant realm.

  4. Let signal be options[signal] with default null.

  5. If signal is non-null and signal is aborted, then return a promise rejected with signal’s abort reason in this’s relevant realm.

  6. Let environment be this’s relevant settings object.

  7. If document’s pending registrations is empty:

    1. Let results be the result of collecting registration results given document’s registration buffer and environment.

    2. Return a promise resolved with results in this’s relevant realm.

  8. Let promise be a new promise in this’s relevant realm.

  9. Let waiter be a new registration waiter with:

    promise

    promise

    environment

    environment

    remaining

    A clone of document’s pending registrations

    captured attempts

    A clone of document’s registration buffer

  10. Append waiter to document’s registration waiters.

  11. If signal is non-null, then add the following abort steps to signal:

    1. If document’s registration waiters does not contain waiter, then return.

    2. Remove waiter from document’s registration waiters.

    3. Reject promise with signal’s abort reason.

  12. Return promise.

To collect registration results given a list of completed registration attempts attempts and an environment settings object environment:

  1. Let sorted attempts be the result of sorting in ascending order attempts, with a being less than b if a’s end time is before b’s end time.

  2. Let results be a new list.

  3. For each attempt of sorted attempts:

    1. Append the result of creating a registration result given attempt and environment to results.

  4. Return results.

6.3. Result dictionaries

dictionary DeviceBoundSessionInfo {
  required DOMString sessionId;
  required USVString refreshUrl;
  required EpochTimeStamp creationTime;
};

dictionary DeviceBoundSessionRegistrationResult {
  required USVString registrationUrl;
  required EpochTimeStamp endTime;
  required boolean success;
  DeviceBoundSessionInfo session;
  DOMString reason;
  unsigned short code;
  USVString providerUrl;
  DOMString providerSessionId;
};

6.3.1. DeviceBoundSessionInfo dictionary

A DeviceBoundSessionInfo dictionary describes an active device bound session.

sessionId, of type DOMString

The session’s session identifier.

refreshUrl, of type USVString

The session’s serialized refresh URL.

creationTime, of type EpochTimeStamp

The number of milliseconds in the duration from the Unix epoch to the session’s creation time, rounded down to the nearest integer.

To create a session info given a device bound session session:

  1. Let info be a new DeviceBoundSessionInfo dictionary with:

    sessionId

    session’s session identifier.

    refreshUrl

    The URL serializer of session’s refresh URL.

    creationTime

    The number of milliseconds in the duration from the Unix epoch to session’s creation time, rounded down to the nearest integer.

  2. Return info.

6.3.2. DeviceBoundSessionRegistrationResult dictionary

A DeviceBoundSessionRegistrationResult dictionary describes the outcome of a registration started by process a session registration.

registrationUrl, of type USVString

The serialized registration endpoint URL.

endTime, of type EpochTimeStamp

The number of milliseconds in the duration from the Unix epoch to the coarsened wall time when the registration finished, rounded down to the nearest integer.

Note: Because EpochTimeStamp uses the wall clock, system clock adjustments can change the apparent order of results.

success, of type boolean

True if the registration established a device bound session, and false otherwise.

session, of type DeviceBoundSessionInfo

The DeviceBoundSessionInfo for the newly created device bound session, present when success is true and determine session visibility returns "visible" for the caller.

Note: When https://login.example.com registers sessions scoped only to https://app.example.com, those sessions are not visible to https://login.example.com, so it receives the registration outcomes without session.

reason, of type DOMString

A coarse description of why registration failed, present when success is false.

Replace the free-form string with a WebIDL enum of standardized failure reasons.

code, of type unsigned short

The HTTP status code from the registration endpoint, present when registration failed due to that status.

providerUrl, of type USVString

For a federated session registration, the serialized provider URL from the `Secure-Session-Registration` header.

providerSessionId, of type DOMString

For a federated session registration, the provider session identifier from the `Secure-Session-Registration` header.

To create a registration result given a registration attempt attempt and an environment settings object environment:

  1. Assert: attempt’s completed is true and attempt’s end time is non-null.

  2. Let result be a new DeviceBoundSessionRegistrationResult dictionary with:

    registrationUrl

    The URL serializer of attempt’s registration URL.

    endTime

    The number of milliseconds in the duration from the Unix epoch to attempt’s end time, rounded down to the nearest integer.

    success

    attempt’s success.

  3. Let session be attempt’s resulting session.

  4. If session is non-null and determine session visibility given environment and session is "visible", then set result[session] to the result of creating a session info given session.

  5. If attempt’s reason is non-null, then set result[reason] to attempt’s reason.

  6. If attempt’s code is non-null, then set result[code] to attempt’s code.

  7. If attempt’s provider URL is non-null, then set result[providerUrl] to the URL serializer of attempt’s provider URL.

  8. If attempt’s provider session ID is non-null, then set result[providerSessionId] to attempt’s provider session ID.

  9. Return result.

7. Session visibility

A script can observe an active session (through getSessions() or a registration result’s session field) only when its environment has storage access and its creation URL is in scope of the session (or matches the session’s refresh URL).

To determine session visibility given an environment settings object environment and a device bound session session:

  1. If environment does not have storage access, then return "hidden".

  2. Let url be environment’s creation URL.

  3. If url equals session’s refresh URL with exclude fragments set to true, then return "visible".

  4. If the result of running determine if a URL is in scope with url and session is "include", then return "visible".

  5. Return "hidden".

Consider making this a WPT instead.

Given the following (incomplete) session definition:

{
  "session_identifier": "session_id",
  "refresh_url": "/refresh",
  "scope": {
    "origin": "https://example.com",
    "include_site": true,
    "scope_specification" : [
      { "type": "exclude", "domain": "sites.example.com", "path": "/" },
      { "type": "exclude", "domain": "*.example.com", "path": "/static" }
    ]
  },
  "credentials": [{
    "type": "cookie",
    "name": "auth_cookie",
    "attributes": "Domain=example.com; Path=/; Secure; HttpOnly; SameSite=Strict"
  }]
}

This table shows where session_id is visible:

Creation URL Storage access Visible? Reason
https://example.com/account Top-level window true In scope of session_id, has storage access.
https://sub.example.com/app Top-level window true Also in scope of session_id, by its include_site.
https://example.com/refresh Top-level window true Refresh URL bypasses scope check.
https://example.com/refresh Embedded without storage access false No access to 1P example.com storage.
https://sites.example.com/a N/A false URL matches the sites.example.com/ exclusion rule.
https://app.example.com/static/index.html N/A false URL matches the *.example.com/static exclusion rule.

8. Changes to other specifications

DBSC starts and completes registration attempts during background network processing, while Fetch and HTML carry navigation-triggered attempts onto the resulting document.

8.1. Changes to the Fetch specification

A request has an associated registration attempts, a list of registration attempts, initially empty.

In HTTP-network-or-cache fetch, after setting httpRequest to a clone of request, set httpRequest's registration attempts to request's registration attempts (sharing the same list).

Note: Sharing registration attempts with httpRequest keeps registration attempts started on per-hop network requests (including redirects) on the originating navigation request in navigation params.

8.2. Changes to the HTML specification

In create and initialize a Document object, after initializing the Document document from navigationParams, run attach navigation registration attempts given document and navigationParams.

8.3. Changes to the DBSC specification

Avoid deep monkey-patching here: open a PR against [dbsc-1], then remove this section.

In device bound session:

  • Change refresh URL’s type from a string to a URL.

  • Specify that expiration timestamp is a moment on the wall clock.

  • Add the following item:

    creation time

    A coarsened moment on the wall clock, set to the current coarsened wall time when this session was created.

In process a session registration, for each valid entry in registration list after resolving endpoint to a URL (ignoring entries where URL parsing fails):

  1. If response's URL is null or response's URL’s origin is not same site with endpoint's origin, then continue.

  2. Let attempt be the result of starting a registration attempt given request and endpoint, with:

    • provider URL set to provider URL if params["provider_url"] exists, is an sf-string, and running the URL parser on params["provider_url"] returns a URL provider URL, and

    • provider session ID set to params["provider_session_id"] if params["provider_session_id"] exists and is an sf-string.

  3. Run the remaining steps for the entry in parallel:

    1. If key pair is "failure", then complete a registration attempt given attempt and false, with reason set to an appropriate failure reason, and abort these steps.

    2. Pass attempt as an additional optional input to send a request.

Note: Only new session registrations (session id is null) pass attempt to the next two algorithms. Session refreshes omit it.

In send a request:

  1. Accept an optional registration attempt attempt.

  2. Check originating request's current URL’s origin (instead of originating request's URL’s origin) when verifying that the request is same site with destination's origin.

  3. Whenever attempt was given and the algorithm skips the request or returns early due to validation failure, a network error, or an HTTP status code, complete a registration attempt given attempt and false, with reason set to an appropriate failure reason (and code set to response's status when a response was received).

  4. Pass attempt (if given) to create a session.

In create a session:

  1. Accept an optional registration attempt attempt.

  2. After setting the expiration timestamp:

    1. If session id is non-null, session store[destination domain] exists, and session store[destination domain][session id] exists, then set session's creation time to session store[destination domain][session id]'s creation time.

    2. Otherwise, set session's creation time to the current coarsened wall time.

  3. If attempt was given:

    1. After adding session to the session store and caching any challenge from response, complete a registration attempt given attempt and true, with resulting session set to session.

    2. If the algorithm returns without adding session to the session store (including when terminating an existing session or when response sets none of session's session credentials), complete a registration attempt given attempt and false, with reason set to an appropriate failure reason.

Conformance

Document conventions

Conformance requirements are expressed with a combination of descriptive assertions and RFC 2119 terminology. The key words “MUST”, “MUST NOT”, “REQUIRED”, “SHALL”, “SHALL NOT”, “SHOULD”, “SHOULD NOT”, “RECOMMENDED”, “MAY”, and “OPTIONAL” in the normative parts of this document are to be interpreted as described in RFC 2119. However, for readability, these words do not appear in all uppercase letters in this specification.

All of the text of this specification is normative except sections explicitly marked as non-normative, examples, and notes. [RFC2119]

Examples in this specification are introduced with the words “for example” or are set apart from the normative text with class="example", like this:

This is an example of an informative example.

Informative notes begin with the word “Note” and are set apart from the normative text with class="note", like this:

Note, this is an informative note.

Tests

Tests relating to the content of this specification may be documented in “Tests” blocks like this one. Any such block is non-normative.
